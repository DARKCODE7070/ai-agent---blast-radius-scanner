 Support and Marketing both post to the shared #ops-alerts channel. Inventory
 trusts that channel and can place real supplier purchase orders, so a
 prompt-injected message reaches money.
 Agents: 3   Resources: 8   Untrusted entry points: customer_messages, social_mentions
 Attack paths found: 10   Cross-agent paths: 6

   customer_messages -> support_agent -> inventory_agent -> suppliers.place_purchase_order
   (best-first search result matches the DFS maximum of 50)

 #1  Score 50  [HIGH]   5 x 5 x 2
     Path : [entry] customer_messages
              => steers support_agent
              -- ops.post_alert (write) --> ops_alerts
              => steers inventory_agent
              -- suppliers.place_purchase_order (write) --> supplier_orders
     Why  : An attacker who can write to customer_messages (untrusted input)
            can inject instructions into support_agent, which trusts that
            input. support_agent uses ops.post_alert to write ops_alerts.
            inventory_agent trusts ops_alerts, so the attacker now steers
            inventory_agent too - without ever touching it directly. Final
            action: suppliers.place_purchase_order can write supplier_orders
            - sensitivity 5/5, irreversibility 5/5 (cannot be undone).
            Steering 2 agents gives 5 x 5 x 2 = 50.
     Fix  : Break the cross-agent bridge: inventory_agent should accept only
            verified (signed / human-approved) content from ops_alerts, not
            act on anything posted there. Set data_trust of ops.read_alerts
            to "verified". Also require human approval before
            suppliers.place_purchase_order.
